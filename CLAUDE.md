# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Let's Play!": an all-in-one app for a ~6–7-year-old that combines three of the owner's games behind one launcher (the "hub") with ONE shared daily play-time limit set by a grown-up. Tablet first, also iPhone.

```
index.html               the hub: storybook launcher, shared play time, grown-up settings, shared sleep scene
games/bus3d/             Little Bus Captain (the 3D bus game the hub opens; first called Bendy Bus 3D): index.html, vendor/three.min.js (three r149, MIT), js/*.js; landscape
games/bus/               the old 2D Bendy Bus, no longer opened by the hub or cached (kept for reference)
games/grizzly/index.html Grizzly and the Lemmings (20 mini games), canvas 960x540, landscape
games/mrt/index.html     MRT Math Express, DOM, portrait-phone first
icons/, manifest.webmanifest, .nojekyll   hosting (icons drawn with the hub's art: node icons/make-icons.js)
sw.js                    the service worker that makes the Home Screen app work offline
```

No build step, no dependencies; everything is drawn and synthesised in code and works offline from `file://` (Little Bus Captain needs WebGL).

The owner reviews as a player, from screenshots and a link, not from code. Report in plain language and send screenshots of visible changes.

## Commands

There is no build step, linter or test suite. The everyday commands:

- **Syntax check** (the only "lint"; a syntax error blanks the whole game): `for f in games/bus3d/js/*.js; do node -e "new Function(require('fs').readFileSync('$f','utf8'))" || echo BAD $f; done`
- **Try it:** open `index.html` (the hub) or `games/bus3d/index.html` from `file://`, or serve the folder with `python3 -m http.server`.
- **Test a change:** copy `games/bus3d` (or the whole app, for hub tests) to a scratch folder and test the copy, never `/home/user`. Headless Playwright needs `chromium.launch({ args: ['--use-gl=swiftshader', '--enable-unsafe-swiftshader'] })` to draw the 3D game at all (a few fps). The usual flow: seed `localStorage['bus3d.save']` (e.g. `{jobsDone: 6, questions: 14, seen: {add: true, sub: true}, vehiclesOwned: [...]}`), stub `speechSynthesis.speak` to log the lines, then click "Play" and "Drive!" with `{ force: true }` (the buttons bob, so normal clicks time out). Jump to the current stop: `const j = BB.jobs.current, s = j.stops[j.index], bay = BB.world.bayOf(s); BB.bus.setPose(bay.nose.x - bay.fwd.x * 3, bay.nose.z - bay.fwd.z * 3, bay.heading); for (let i = 0; i < 60 && !BB.bus.atStop; i++) BB.update(0.05);` and answer by tapping the `.bbq` button whose text is `BB.jobs.question.answer` (pointerdown, pointerup, click). Hub tests: open the hub's `index.html` and call `__hub.open('bus')`, then reach the game with `page.frames()`.
- **Preview build:** the preview Artifact is a scratch copy of the app with the hub stripped by the `sed` line below and `<title>` "Let's Play! Preview". At the owner's request everything is unlocked in it: in the copy's `depot.js`, `ownsVeh`, `partOwned`, the paint and sticker `own` checks return true, both Extras are set (`S.upgrades.horn`, `S.upgrades.sticker3`) and the starting cash is at least 500; after copying in a changed `depot.js`, re-apply all of them and check the shop shows no price chips (the other helpers' edits can move the lines). Those edits live only in the scratch copy; never commit them, and check `grep -c "PREVIEW BUILD" games/bus3d/js/depot.js` is 0 before a release.
- **Release (after the owner says "go"):** if this release has no number yet, raise `APP_VERSION` by one in both `index.html` and `sw.js` (they must match; `sw.js` builds `VERSION` from it) and add a `CHANGELOG` entry for it in `index.html` (plain words a parent understands, newest first), push the branch, fast-forward `main` to it (`git push origin HEAD:main`), confirm the "pages build and deployment" run for that commit succeeded, then rebuild and republish the main Artifact (if this session didn't publish its files, read them with the Artifact tool first, or the publish is refused).

## Published copy

`main` is served by GitHub Pages from the repo root at https://hermannwwr-cmyk.github.io/letsplay/. Every push to `main` redeploys it within a minute or two. Cloud containers usually can't reach github.io (the proxy refuses it), so confirm a deploy with the "pages build and deployment" workflow run for that commit (GitHub MCP `actions_list`). `.nojekyll` turns off Jekyll.

The owner also has a private claude.ai Artifact copy titled "Let's Play!" (https://claude.ai/artifact/3HjW7hseEgPHX7MHT1sJvp). After a change, rebuild it in a scratch folder and republish it to that URL, with the hub as the page and the game files (`games/bus3d/index.html`, `vendor/three.min.js`, `js/*.js`, `games/grizzly/index.html`, `games/mrt/index.html`) as supporting files at the same paths (the games' icons and manifests aren't needed). The host supplies the document skeleton, so strip it and the head tags from the hub:
```
sed -e '/^<!DOCTYPE html>/d' -e '/^<\/\?html/d' -e '/^<\/\?head>$/d' -e '/^<\/\?body>$/d' -e '/^<meta /d' -e '/^<link rel=/d' index.html > lets-play.html
```
Keep `<title>` and `<style>` near the top of `index.html` and each head tag on its own line, so this stays a line deletion. `sw.js` isn't needed in the Artifact (the hub only registers it on https in a top-level page, and a failed registration is ignored).

**Offline Home Screen app (`sw.js`):** a small versioned service worker, registered from `index.html` only when `location.protocol === 'https:'` and the hub is the top window (never from `file://`). On install it precaches the hub, the game files and the icons/manifest (`CORE`; the games' own icons and manifests are `EXTRA`, skipped if missing), then `skipWaiting()`; on activate it deletes every other cache and `clients.claim()`s. Pages and code (`.html`, `.js`, `.css`, `.webmanifest`, navigations) are network-first with a cache fallback, fetched with `cache: 'no-cache'` so GitHub's `max-age=600` doesn't delay a push (a cheap 304 when unchanged). An error answer (404, 503) or a network slower than 4 s falls back to the cached copy (the fresh copy still lands in the cache), so a push shows up on the next launch with a connection. Redirected responses, or ones whose URL isn't the requested file (a Wi-Fi login page), are never cached. A redirect or a different page while online is treated like an error answer (the cached copy is used). A failed install removes the empty new cache; icons and images are cache-first; the bus game's Google Font is cached at runtime in `lets-play-fonts`. Lookups ignore the query string (games load as `index.html?hub=1`). **Bump `APP_VERSION` in `sw.js` and `index.html` (with a `CHANGELOG` entry) on every release** (any change to `index.html`, `games/` or `icons/`), and add new files to `CORE`: a missing `CORE` file makes the install fail and the old copy stays. To test it locally, serve a scratch copy and relax the https check to allow `localhost` (a secure context); Playwright's `context.setOffline(true)` after a first load simulates the offline relaunch.

**Previewing before going live:** a push to `main` goes public at once, so visible changes are shown to the owner first and pushed to `main` only after they say go. Show options as screenshots (before/after sheets at phone and iPad sizes), then build the chosen one into the preview Artifact "Let's Play! Preview" (https://claude.ai/artifact/TsjDv2hfXpHCB2ba5Lv4v5; same build, with `<title>` changed to match). Meanwhile commit the work to the `claude/dazzling-albattani-67ajm8` branch (Pages doesn't serve it), then fast-forward `main` to it on approval and republish the main Artifact.

## Where the games come from

The games are copies of the owner's standalone games, plus a small "hub mode" patch in each:
- Bus: Little Bus Captain (first called Bendy Bus 3D) was built here (`games/bus3d/`, brief in `games/bus3d/SPEC.md`, partly outdated (where it and this file disagree, this file wins): the owner later chose free driving with a steering wheel and Go/Back pedals (the only control; the joystick was removed) plus an optional lane helper, left-hand traffic, two lanes each way, side-view stops with a dollhouse cut-away, three generic Singapore bus types plus five drivable vehicles (taxi, fire engine, ambulance, ice cream van, tow truck), real parts in the garage, no faces on vehicles, a written sum with pictures, a 6-minute day cycle with ~30 s of night, weather). It has no standalone repo; the old 2D bus came from the `Bendy-Bus-Game` repo's `gh-pages` branch.
- Grizzly: the `Grizzly-and-the-lemmings-game` repo's `index.html` (its CLAUDE.md documents the game in depth).
- MRT: the `MRT-GAME` repo's `index.html` (its CLAUDE.md and `tests/play.js` document and test it).

Hub mode only switches on with `?hub=1` inside an iframe (`const HUB = /[?&]hub=1\b/.test(location.search) && window.parent !== window`). Without it each copy behaves exactly like the original. To bring in a newer version of a game, re-apply that game's hub-mode code (everything guarded by `HUB`, plus the hub-only CSS) to the new file. The hub-mode code exists only here, not in the original repos. This repo starts from a single import commit, so diff `games/<game>` against the original game's file to see exactly what hub mode adds (the step-by-step history is on the `claude/dazzling-albattani-67ajm8` branch of `Bendy-Bus-Game`, where the app was first built; that branch is no longer updated).

## Hub ↔ game protocol (postMessage, always to `'*'`)

In `file://` the frames have opaque origins, so never touch `parent.document` and don't rely on storage shared between hub and game. Ignore messages that aren't objects with a `hub` string; games also check `e.source === window.parent`, and the hub checks that messages come from the current frame.

| from → to | message | when |
|---|---|---|
| game → hub | `{hub:'hello', game}` | script start; the hub closes a frame that hasn't said hello within ~6 s |
| game → hub | `{hub:'exit'}` | child taps the "all games" button |
| game → hub | `{hub:'sleep'}` | the game's own gentle bedtime ending has finished; the hub treats it as the end of the day |
| game → hub | `{hub:'stars', count}` | optional, for the stars shown on the launcher |
| game → hub | `{hub:'sound', mute, music}` | the child tapped the game's own 🔊 or 🎵: the full new shared setting (both booleans). The game applies it at once; the hub saves it (`hub-mute`, `hub-music`), updates its own icons and sends a time message straight back with it |
| hub → game | `{hub:'time', limit, left, used, share, mute, music}` | about every second, on hello, and at once whenever the sound setting changes; `left` is null and `share` 0 when the limit is off. `mute: true` = all sound off (music, effects, voice); `music: false` = music off only |
| hub → game | `{hub:'hold', on}` | `on:true` when the "turn me sideways" card covers a running game, `on:false` when it goes. The game freezes (no updates, timers or speech, sound suspended) and then carries on exactly where it was. Bus re-says the line that was cut off, or the question on screen. MRT is never covered and ignores it. |
| hub → game | `{hub:'pause'}` | right before the frame is removed |

In hub mode every game: doesn't count time or touch its own play-time storage; doesn't read or write its own saved sound/music switches (it starts with sound and music on until the first time message, which comes on hello, and its buttons always show the hub's values; its 🔊 means all sound off); hides its own grown-up gear/gate/settings; shows the shared **all-games button** top-left on its start screen (a 64px cream paper circle, at least 56 CSS px on phones, fill `#fff6e0`, rim `#d9b57f`, with a 2×2 grid of rounded cards `#f26b5b` `#f5b83d` / `#5cb85c` `#4fa3e0`, bobbing gently); shows the shared clock chip look (cream pill, drawn clock, m:ss, orange with a moon in the last minute); runs its own gentle bedtime ending and then posts `sleep` once; never starts a new round once time is up; and fills the screen around its canvas with a cheap continuation of its own scene (Grizzly, Bus; no per-frame pixel reads, no CSS blur, dimmed and tinted with the picture). All three send `hello` at the end of their setup.

- **Grizzly:** the menu gear spot becomes the all-games button (grown by `hubExitR()` on small screens, with the "N min" chip moved along). Round games check `lastTurn()` before starting a new round: once `timeUp()`, the next finished turn gets a sleepy "Goodnight!" card and line, then `sleep` (Grizzly's own sleep scene and speech never show in hub mode). Continuous action games (Leap, Rafts, Bounce, Boop, Catch, Stack) freeze their difficulty and tips once time is up and say goodnight at a calm moment about `CONT_GRACE` (35 s) after zero, never mid-jump; `BEDTIME_GRACE` (150 s) is the last safety net. The backdrop (`hubBackdrop()`/`paintHubBackdrop()`) is a half-resolution canvas repainted at most twice a second: canopy or sky on top, meadow below, and on phones a vertical gradient of the scene's layers (`hubSideStops()`). The main loop's update/render is wrapped in try/catch so one error can't freeze the game.
- **MRT:** `#homeClock` becomes the all-games button (inline SVG), and the all-games button also shows on the end screens. In hub mode `<html>` gets a `hub` class for layout tweaks that fit the hub's inset iPhone frame (about 390×763). Its "2 more stops" flow starts at 60 s left (at once if a ride starts with 60 s or less), so its bedtime ride usually ends before zero; the train always says goodnight (also when time runs out on the start screen or a normal end screen, after "Hooray!"), and `sleep` is posted ~7 s into the sleepy end screen. Direction signs on the start picker and at interchanges take two taps: the first lights the sign and speaks where it goes, the second takes it. On sideways screens the game screen splits into station (left, sized by `fitScene()`) and question (right) with no scrolling.
- **Bus (Little Bus Captain, `games/bus3d/`):** three.js scene, classic scripts sharing `window.BB` (core, fleet, world, bus, jobs, depot, ui, main). Opens on its own home screen (title, the child's bus, one big Play button to the garage, a friends count, the Book tile bottom-left and the wish card bottom-right); the garage has the ride (bus types and the other vehicles), colour, number, parts shop, settings and free fuel. Hub mode: clock chip, last-minute warning between stops (never during a question; `BB.jobs.busy()`), the sky eases to night in the last minute, goodnight after the stop in progress (passengers walk off, lights off, "Goodnight, bus!") then `sleep` once; never starts a new job after time is up. `{hub:'stars'}` = jobs done. Hold and a hidden page freeze the loop and `BB.later` timers; use `BB.later`/`BB.cancelLater`/`BB.wait` for new timers. The all-games button (with a "Home" tag) is on the game's home screen only; the driving HUD's and garage's Home tiles go back to that home screen.

## Little Bus Captain (`games/bus3d/`)

About 17,000 lines of classic `<script>`s (not ES modules, which fail from `file://`) sharing one global `window.BB`, loaded in this order by `index.html`: `vendor/three.min.js` (global `THREE`), `core.js`, `landmarks.js`, `fleet.js`, `world.js`, `bus.js`, `hands.js`, `jobs.js`, `depot.js`, `ui.js`, `net.js`, `events.js`, `main.js`. Each file adds its own CSS through `BB.css`. Modules talk through an event bus (`BB.on(name, fn)` / `BB.emit(name, data)`); grep `BB.emit('` for the full list.

### Modules

- **core.js:** the event bus, `BB.store` (localStorage keys `bus3d.*`, try/catch) and `BB.save` (one object saved as `bus3d.save`: paint, parts/partsOwned, stickers, upgrades, fuel, jobsDone, questions, `skill`, `wish`, `wishTold`, `stamps`, `seen`, busType, routeNo, assist, leftHand, control; `DEFAULT_SAVE` plus checks on load), `BB.mk` (merges flat-shaded vertex-coloured parts into one mesh), `BB.pic` (flat canvas icons), sound effects and the looping tune, `BB.say`/`BB.heard` (a warm storyteller voice when the device has one: `KID_VOICES`, e.g. Samantha/Karen/Moira on Apple devices, Google UK English Female on Android; rate 0.88, pitch 1.1), hold-aware timers `BB.later`/`BB.cancelLater`/`BB.wait`, `BB.setHeld()`, and hub mode (`BB.HUB`, `BB.hub`, the protocol).
- **fleet.js:** `BB.fleet.build(type, paint, opts)` for the three bus types (`bendy`, `double`, `single`; generic, no branding): carriages, hitch, axles/wheelbase, door proxies, `seatsLocal` (10 seats, ten-frame order; row 2 raised and offset half a seat so both rows read from the side), `kerbWallParts` (faded at stops for the dollhouse view), `roofParts`, part mounts, wipers, `routeSign.setNumber()`. Paint uses a shader patch (paint-flagged vertices take `material.color`); doors and wipers move in the vertex shader. `preview()` makes the garage tiles.
- **world.js (`BB.world`):** the town on a road graph (`nodes`, `edges` with `points`, two lanes each way, left-hand traffic; `C.block`, `C.roadHalf`, `C.lane` set here), 61 stops with picture signs (11 named, the rest small automatic stops) plus about 67 roadside scene spots for the other vehicles, the depot, landmarks, HDB blocks, the town's life (walkers, little cars, sailing boats: see "Town life" below), `colliders` (`addCircle`/`addBox`/`pushOut`, `blocksSight` for cameras), the day cycle (`setDayTime`, `day`, `night()`; in hub mode the last minute eases to night and stays) and weather (`setWeather`, `isRaining`, rain as one draw call). `prewarm()` compiles the weather shaders at load.
- **bus.js (`BB.bus`):** free driving from `B.input` (`{analog, throttle, steer}` from the joystick or wheel, or the old booleans), trailer physics for the bendy, collision circles that slide along colliders (never stuck: slide, then hop free), the optional lane helper (`B.assist`: follows the ribbon, hands over to parking in the last ~34 m), the guide ribbon, settling into a bay and `bus:arrived` (forgiving: anywhere from 8 before to 12 past the box, either lane on that side, at up to a gentle roll (speed < 7), then a 0.5–1.1 s glide in, so a child never has to reverse), `stopAt(stop|depot|null, cb)`, fuel, the turn-around hop, cameras (`setCamera`: chase, which fits the ride: it is placed from the ride's tail and aimed past its nose, so a bendy bus shows whole and the two other buses look as they always did, and rides shorter than a bus (taxi 5 long to fire engine 8.4) are seen from closer and lower by one share, `fit` 0.7–1, so a taxi isn't a speck; the side-view stop camera chosen once per stop/bus type/screen size: on tablets, where the card is along the bottom, the bus stands just above the card and the people come first, so a long bus's tail may be cut off; the plan also reads `stop.queue` (friends are waiting: their strip of pavement must show, so the bus moves over to the right on tablets, up a little on phones, and the picture pans so their feet and the rings round them stand clear of the card and the screen's edge; where the usual view is steeper than 24° or the friends don't fit it well, `planned()` also plans the strip on the bus's other side, a wider lens (the camera stands nearer, past a building right behind the pavement), the view without the strip and, if all are still steep, the other side with the wider lens, and asks jobs.js how well the friends' row fits each one (`BB.jobs.queueFit(frame)`, with `queueFrame()`: the bus as it will stand once settled): a view that hides some of the friends never wins over one that shows them all however steep; among those, the lowest look wins, a little worse with smaller rings, toes cut by the card, or friends shorter than about a sixth of the screen; measured over every stop, all three buses, iPad and phone: no friend hidden, cut by the edge, behind a post or with a cut ring, and only the bendy at stop44 looks down more than 40°; planning takes at most about 12 ms, once per stop on arrival), a scene target's `frameClose` (a close-up of the scene's own points only) and `framePitch` (the least the camera looks down: the tray scenes use 26°, their near row a long step nearer and between the far row's things); a job's scene stands just above the card on tablets (like the bus) and is first tried from the nearer spot, so its little things aren't tiny; `stopView()` gives the planned view before the camera has got there, for laying people out; depot views), `bodyBox()` (the body's corners, for a "tap the fire engine" ring), `setType`, `setRouteNumber`, `setPart` (lights, bumpers, wheels, rims), stickers, `makeTowTruck()` (one cached truck), `seatWorld(i)`, `doorWorld()`, `exitDoorWorld()`.
- **jobs.js (`BB.jobs`):** jobs of 2–3 stops, people queueing, boarding by the front door and leaving by the exit door, `makeQuestion` (every number 0–10, adding first, taking away later, no repeats in the last 5, "0 left" at most once in 5 questions; a fair mix (`J.kinds`): an empty bus, i.e. the first stop of a job, always picks people up, never more than two taking-away questions in a row nor more than three adding ones, so about two in three bus questions add), difficulty that follows the child (`save.skill` 0–4.6, its whole part is the level in `LEVELS`: +0.4 for a right answer at the first try, unchanged after one wrong try, −0.6 when Mina had to walk through it; nothing is shown or said about it), shuffled answer choices (tappable as soon as the question starts being asked; a tap on the still-faded buttons during the story makes Mina hop with a soft tick and never cuts the story off), short varied hello and praise lines (never the same twice running), the question card (ten-frame plus the written sum `2 + 1 = ?` with person icons under each number), teaching on the real bus (outline rings and number bubbles over heads, Mina the mynah; 1st miss = count together by tapping, 2nd = Mina stops at "?", 3rd = shows it all; first-time worked examples use other numbers), the tow, coins (1 per stop + 2 per finished job, about 50 a day at 15 minutes: slower on purpose, the owner's choice; never taken away), `busy()` / `jobs:busy`, `allOff()` for the goodnight. **Who sits where** (`job.seats`, `noteSeat()`): seat i remembers a friend or the thing its rider got on with, so whoever gets off is the same person again, still carrying their school bag, suitcase, shopping bag or umbrella (seats fill and empty from the top; Home mid-stop restores it from `J.stopStart`). A person's thing is merged into their own mesh (`withProp()`, one draw call each; only a balloon stays separate, it floats off and pops). **The job-done moment** (`celebrateJob()`/`jobDone()`): a banner with a ticket for each job on a dotted path of four ticket places leading to a trophy, and the job's coins, the wish under it. A ticket (`ticketArt()`, drawn once per ride picture) is a teal paper ticket with notched sides and a cream window showing the ride that did that job (its garage picture, `BB.depot.ridePic`; `save.stamps` keeps the rides of the last 5 jobs, older saves show the ride now), so the path reads as "my jobs", never as coins or a score; this job's ticket is stamped on (drops in big and tilted, lands with a squash, a thump and a glow). The trophy waits at the end of the path in full colour (smaller, no number, a wiggle now and then); every 5th job (`save.jobsDone`, the same number as the launcher's stars) it wins with that number, a gold rim, a fanfare, confetti and a toot of our own horn (`BB.sfx.horn`, not `BB.bus.horn`, so friends nearby get no honk; no toot once time is up). The job's 2 coins fly from the banner's coin up and round into the coin counter (`flyCoins(el, n, land)`; `BB.depot.add(n, { quiet: true })` adds them without the "+2" pop over the banner, and the counter goes up as they land, `BB.ui.coinsLanded()`). When time is up the wish card is left out, and it goes at once if the goodnight starts while it shows (`dropWish()`). Spoken: the trip's own words ("Taxi job done!", "School trip done!") or one of a few everyday ones, then at most one more line, chosen only when it is about to be said: the trophy, else enough coins for the wish (`BB.depot.wishNews('job')`, now and then), else "One more job for a trophy!", else how many more coins the wish takes. Stop names (`nextNear(from, exclude, strict)`): not one already heard in this job or where the bus is, from the usual hop or a little further (up to ~130 road units); a job's third stop only with a new name (`strict`; `pickStops()` tries a few other second stops, else the job has two stops), so a job never goes "the seaside, the sea view, the seaside"; where only one name exists for a long way (old town, the airport road) two stops in a row may share it, and `stopLine()` says "drive to the next old town stop!". After the garage or the tow, new stops are picked from the depot yard (`J.lastStop` is cleared). **Playing together** (`meetPoint()` / `meetPick()`, used by `nextNear` and `legTo`): while friends are out driving (`BB.net.driving()`), new stops bring everyone to one player, the leader (of all who are out driving, the lowest member id, the same on every device; the leader plays on in its usual short hops, leaning towards the others (`leadPool()`), so the meeting place moves slowly): far from the leader (over 70 units), the next stop is one of the two nearest to them that bring us nearer, however long the drive; near them, short hops that stay within about 85 units; no themed trips meanwhile, and a bus job's later stops are chosen afresh at each stop (`nextStop`). Buses still go to bus stops and the other rides to their own spots. With no friend driving nothing changes.
- **hands.js (`BB.hands`, `BB.water`):** the hands-on moments. During a question's story the child DOES its "k" part with a finger, then answers as before. `BB.hands.run(opts)` runs one moment over the 3D scene (a DOM layer in `#ui` under the HUD and the card; targets are world points projected every frame) and resolves when it is done: kind `tap` (`repeat` = one target tapped k times; `ordered` = the things go in list order whichever is touched; a target `{at, box}` is a whole big thing whose ring goes round its box on screen: "tap the fire engine", `BB.bus.bodyBox()`), `drag` (the thing follows the finger over the ground to the drop place; a drag let go anywhere, or a plain tap, still lands, and a thing pulled up into the sky stays near, so nothing can go wrong), `aim` (the finger points anywhere in the view; the scene calls `BB.hands.hit(i)`), `crank` (a big winch wheel turned round and round, either way; a tap gives a little turn; the track round it fills with teal as the car goes up; it sits below the truck on tablets and in the empty column on the left on phones). **One look for every ride:** a chunky honey ring on what to touch, 88 px (66 on phones; `BB.hands.size()`), never two overlapping: things that stand closer together than a ring share one ring, on the next one (the others can still be touched: the thing nearest the finger is the one meant); a person (a target `{at, feet}`: the waiting friends, the children waiting for a teddy) wears the ring lying flat round their feet like a spotlight (a little narrower where people stand close together), so they stay in full view, and the whole person, feet to head, takes the finger; a dashed teal drop place with a little arrow on the very spot the thing in hand goes (`drop(out, idx, j)`: carried things fill their places in order, whichever one the child picks up, so the card's ten-frame never has gaps; `SCN.look[i]` remembers which picture really stands in place i and the card draws that one, also in a later question on the same scene), which lights up under the finger (`dropFlat`: given to a child, it lies flat round the child's feet); the number bubble (`bubbleFollow`: it rides along with a friend walking to the door); and the pointing paper hand, which shows the gesture from the first moment: it taps (with a ripple), carries along a dotted path to the drop place, slides from one glowing window to the next, or goes once round the winch from its knob. **Every touch gets an answer:** a pop of paper stars, a note that climbs with the count, the number bubble and the number aloud. A touch on nothing is never "wrong": the nearest ring wiggles and the hand goes to it (after two near misses the hint is said, after four the game does one). The wheel takes a finger two ways. Pushed from its middle (a press that starts inside 60% of its radius: the red horn and the spokes, where a thumb lands first) it works like a stick (`'push'`): it turns the way the finger slides, left or right, from nothing once the finger is 9 px sideways from where it began (those 9 px don't count), full lock a little past one wheel-radius, straight again when the finger is back where it began. Where the finger is decides it, so a slide that comes back, or carries on across under or over the middle, always steers the way it goes, whatever the finger did before. On top of that, like a real wheel, a finger going up or down round the SIDES of the rim (beyond 72% of the radius, both ends of a 5 px step there, the step mostly round rather than in or out, and mostly up or down rather than sideways) turns the wheel round with it, either way: a push that reaches the side and goes on round a little keeps turning that way instead of swinging back (the extra, `wind`, slips at the lock). Along the top and the bottom of the rim going round is going sideways, so there the wheel just follows the finger like the stick. A step the stick takes back the other way takes the extra off first (the wheel answers at once), it fades for good as the finger comes in off the rim and is gone by 30% of the radius. And on every move a finger going more sideways than up or down never turns a pushed wheel the other way (if anything would, the wheel waits where it is), so a slide always steers the way it goes; a grid of the critics' finger paths and their mirrors, on phone and iPad, finds no such step. Only something driving right onto it (the bus, a friend's ride, an event's vehicle) sends it away at once.
  - *At a stop (the side view):* the side view never shows a walker, so the only people to count are the question's. Before it comes, walkers keep out of the zone round the bay (20 for a stop, 24 for a scene; it stays until the bus drives off) and of what `SV` says the view will show. As the camera swings round to it, everybody it sweeps over steps out (`sweep`: it comes to rest within a few degrees of where it last swung fast, so this clears the real view even where `SV` guessed wrong); once it slows down nobody walks into the picture (they turn round at its edge), and anybody behind a building in it goes while hidden, so nobody steps out from behind one. A last resort hides anybody still in it once it has stood still for 0.3 s (measured: no walker seen shrinking in a still side view at any of the 60 stops or 67 scene spots, iPad and phone, nor in real jobs).
  - *Walkers* (`buildFolk`/`updateFolk`, one instanced mesh `folk`, at most 40 drawn, limbs swung in the vertex shader): about 185 people stroll along every free stretch of pavement (`folkSegs`; two lanes 1.5 and 2.3 in from the kerb, out along one and back along the other, a loop; never on a road, in the yard, through a lamp post or at a stop; where two stretches meet, the end of one is kept 3.5 from the other; an edge point within 2 of a stretch's end is left out of its line, which otherwise kinked back on itself on the loop's curves, so the people there walked over the same spot). Where each one is follows from the clock, its `phase` and how long it has stood still (`lag`). They wave when the bus drives by (children hop), everybody near hops and waves at the horn, umbrellas go up in the rain, and most are home at night or in a storm. They keep out of what the game needs clear (`folkWant()`): the zone round the bay, the side view (above), 26 round a town event, under the bus or a friend's ride. In view they don't vanish but turn round at the edge of such a place (a jump of `phase` to the other lane at the same spot, eased across by `lw`/`hd`, at most every 2.5 s), turn and hurry out if inside, and turn back from an event's things coming along the pavement (the otters, a runaway trolley). Out of view they are looked at every fourth frame, and a stretch wholly outside the camera's wedge isn't placed on the other frames.
  - *Keeping a step apart:* nobody walks into, or through, the person ahead in the same lane. Each frame every stretch's walkers are placed on their loop (`FS.u`); one who comes within 2.6 of the next one out ahead slows down and stands 1.5 behind (`FS.st`, legs at rest) until there is room (a waver, someone waiting to turn round); a turn round only steps into the other lane where nobody is within 2.6 of that spot, else the walker waits there (`FS.hold`); catching up after a wave and hurrying out of a zone both stop 3.2 behind the next one. Someone who isn't out (gone home, stepped out of sight) never holds anybody up, gets out of their way unseen, keeps a step behind the others out of sight too (so two never come back out together in one spot), and only comes back with 2.2 of room either side.
  - *Town cars* (`buildTownCars`/`updateTownCars`): 10 more instances of the expressway cars' mesh (no extra draw call; `cars.count` drops to the town's ten when the expressway is far) drive the town, the outer roads and the expressway along `LANES`, turning at random. They keep to the lane by the middle line (the kerb lane with its bays stays the bus's); toward the bus and friends' rides alike they wait at a junction one is near (not for the bus standing at a stop clear of the junction box: they drive on past it), keep ahead of one behind and well back from one ahead (out of the chase camera's view); they wait behind a town event's things in the road ahead (10 back from a vehicle's nearest end, so the rubbish truck can back up to its bins), and for something fast coming up behind in their lane (an ambulance, a police car) they pull over into the kerb lane and stop (`lat`, `mw`), or near a junction go on through it; event vehicles in turn slow down behind a town car in their way (`W.townCarNear`, events.js `Driver`). A car is taken off the street only while out of sight: left 125 behind the camera, past `CAR_FAR`, within 75 of a stop in progress, within 38 of an event's things, stuck, or (the tow truck counts cars) in the tow scene's view within 100 of the truck (also in the camera's swing to it; one far off in the haze just drives on). It comes back 80–205 away, mostly ahead of the bus and out of view (a car is in view about two thirds of the time). In view, a car the bus, a friend's ride or an event's vehicle drives right into shrinks away. Their lamps glow at night and they have a flat shadow that darkens with the wet road (`wetU`, shared with the walkers' shadows); the nearest one answers the horn with a soft "meep meep".
  - *Boats* (`buildBoats`): six sailing boats on long ovals off the waterfront, one instanced mesh, drawn only from the south half of the map and when the camera isn't looking away from the sea.
  - *Testing it:* `W.update` can run thousands of frames without rendering, so drive by script (`B.setPose` 70 before a bay, `B.stopAt`, throttle, then 7 s at the stop) through every stop or scene spot in a few seconds, and read the drawn walkers from the `folk` mesh's instance matrices (two closer than 0.45 = walking in each other; part-size and not hidden while the camera is still = a pop). Render only for screenshots.

### Performance and testing

- **Performance budget (older iPads):** about 25–50 draw calls and ≤ ~100k triangles; merged or instanced meshes, blob shadows, no shadow maps, fog. Measured with the chase camera 30 units before each of the 60 stops (iPad size, no job running): about 60k triangles in the middle case and 85k in the busiest views (the old town and the town centre), 29–48 draw calls by day, 40 in the middle case, and up to 50 at night or in the rain (a job's people, marker and ribbon add a few). The town life costs about 3k triangles and one draw call of that (the airport's two moving planes are now far-culled like the districts, which pays for part of it), and about 0.05 ms more of `W.update` per frame on a desktop (its occlusion looks are capped at 6 a frame and the side-view sampling at 14 sight lines a frame, once per stop, so it has no spikes; walkers out of view are looked at every fourth frame). The static town meshes are built "lean" (`lean(builder)` in world.js sets `trim` and `pack`, read by `Builder.geometry()` in core.js): `trim` leaves out triangles no camera can see (undersides of things standing on the ground or pavement, i.e. down-facing below 0.36, since the lowest camera is the garage's wheel view at 0.75; anything under the ground; the hair-thin sides of painted road markings), about a fifth of the town; `pack` stores normals and colours as bytes (town geometry about 10 MB instead of 20). After `geometry()`, `builder.counts` holds the vertices each part kept: per-vertex extras (`aCenter` for fading props, `aGlow` for landmark lights) must be sized from it, after the mesh is made. `geometry()` never changes a part's shape, so unit shapes are shared (`box`, `cyl`, `ball` reuse one shape each and scale it in the part's transform). Vehicles, people and anything whose arrays are copied elsewhere (net.js) are not lean. Colliders are stored by `addCol` with the same fields in the same order, and `W.pushOut` (about 25 calls a frame) uses plain loops and plain-number bounds: keep it that way, it is the hottest function while driving. Automatic quality in main.js (`adaptQuality`): when frames stay slow (smoothed frame time over 25 ms for ~3 s) the pixel ratio steps 2 → 1.6 → 1.3 → 1, and back up after a long smooth spell (at most twice). Keep per-frame code free of garbage: no new objects/arrays in update paths (reuse scratch objects, index loops in hot code, `hypot2()` instead of `Math.hypot`); the stop camera is planned once per stop and frame set.
- **Testing:** drive by script through `BB.bus.input`/`BB.bus.setPose`, `BB.bus.setType`, `BB.jobs`, `BB.depot.open()`, `BB.world.setDayTime/setWeather`; stub `speechSynthesis.speak` to log speech. Test a scratch copy (never serve `/home/user`), one browser at a time.

## The hub (`index.html`)

One canvas, in the Grizzly paper-cut art style (its art kit, palette and the embedded Fredoka font were copied in).
- **Finding your way** (one IIFE, about 3,000 lines): `GAMES` (url, name, spoken name, colour per key) and `ORDER` near the top, then `playTime` with `DEFAULT_LIMIT`, `LIMIT_CHOICES` and `FORCE_SLEEP_AFTER`; the art kit and the heroes (`drawBear`, `drawLemmingAt`, `drawBusHero`, `drawTrainHero`); `layout()` (landscape and portrait placement of the places, path and props); `SKY` and the tints; one `draw<Game>Place()` per place; then the frame lifecycle (`openGame`, `sendTime`, `closeGame`, `updateTransition`, `goSleep`, `LANDSCAPE_ONLY`, `showRotate`/`showOver`/`checkRotate`, `reloadPlayTime`). A fourth game would need a `GAMES`/`ORDER` entry, a place in `layout()`, a `draw…Place()`, a loading scene, and hub mode in the game itself.
- **Launcher:** a panoramic storybook world with three places on paper islands joined by a path: the bendy bus at its stop (Little Bus Captain; long names get smaller letters via `nameFit()`), Grizzly and the lemmings, the MRT train on a viaduct. Places idle-animate and take turns doing a "look at me" act. A tap pops (pointerdown), then on pointerup squashes, plays a sound, speaks the name, throws confetti, zooms in and closes an iris in that game's colour with its hero bouncing while the frame loads. Landscape: places side by side; portrait: zig-zag down the hills. Arrow keys / Enter / 1–3 / M work too.
- **Turn sideways:** Grizzly and Bus are landscape games. On a portrait screen the hub shows a "Turn me sideways!" card instead, opens the game when the device turns, and covers a running game (not counting time) if it's turned back upright, also while the game is still loading or being revealed (the hold is sent again when the game says hello). MRT opens in any orientation. On a tablet-sized screen (`min(screen.width, screen.height) >= 700`) whose window clearly doesn't fill the screen either way round (`narrowTabletWindow()`: iPad Split View, Slide Over, Stage Manager) the card also offers a small "Play anyway" button (`playAnyway()`, sets `state.anyway` so that game isn't covered again until it closes); a full-screen iPad held upright and phones never show it.
- **Game frame:** Bus and Grizzly get the whole screen (they letterbox their own canvas, with buttons clear of the notch). MRT, edge-to-edge DOM, gets an inset frame (`iframe.game.inset`, inset by the hub's safe areas `--sat` etc., since WebKit doesn't pass them into frames), so it isn't under the notch or home indicator; `paintFrameBg()` paints the strips in MRT's own page colours (start-screen sky gradient with the viaduct deck under it, its night sky on the sleepy end screen, `--bg` otherwise), reading MRT's `body[data-screen]` / `.night` in a try/catch when the frame is same-origin and using the start-screen colours from `file://`. On the start screen the sky is laid over the frame's area so it carries on into the side strips, the top strip is MRT's exact top colour and its sun glow continues across the seam, and `#frameDock` / `#frameDeck` copy MRT's `.start-dock` background (flats, trees, viaduct) into the strip on the dock's side and its deck colour under it (read every 400 ms). While a game fills the screen (`gameShown()`), the hub's draw loop and music scheduling stop and its canvas and painted layers are freed (`sleepLoop()`); `wakeLoop()` restores them (closing, the sideways card), lays out again if the window changed meanwhile, and the painted layers are rebuilt behind the closed iris (`warmLayers()`). `resize()` does nothing when the size, DPR and safe areas haven't changed; clouds, birds and fireflies keep their own random numbers so a resize re-places rather than reshuffles them.
- **Play time:** storage `hub-limit` (minutes, default 15; Off/10/15/20/30) and `hub-play` = `{day:'Y-M-D' (no zero padding), used: seconds, extra: minutes}`. Counts whole seconds only while a game frame is showing (after hello, no transition, no modal, no sideways card, page visible), and never past the allowance. Re-reads on `storage` events and when the page becomes visible. The top bar is small paper pieces: a borderless cog (grown-ups) top-left, a cream time pill beside it (a sun in a ring that empties and turns into a moon; orange in the last minute; tapping it speaks the minutes left, at most every 3 s of real time, and never opens settings). Minutes left are shown and spoken the same way everywhere (`fmtLeft`): whole minutes rounded up, and "under 1 min" in the last minute (pill, speech and settings), and one music|sound capsule hanging on short strings top-right (no strings below 420 px height). Positions come from `barGeom()`, clouds fade out behind the bar (`cloudClear()`), and the portrait title sits below the bar; the sky follows `share()` from dawn to night, with warm window and lamp light drawn after the night tint.
- **Bedtime:** at zero the game finishes the turn and posts `sleep` (fallback: force-sleep 3 minutes past zero). A `sleep` that arrives while the frame is already closing because the child chose to leave is ignored (the closing still goes to bed if the time is up). The shared sleep scene shows everyone asleep with a lullaby (drawn at about 30 fps; on upright screens the "Time to sleep!" card moves up and shrinks to stay above the sleeping train's station); places can't be opened; it survives reloads. Adding time in the settings wakes everyone. A new day also ends the sleep scene, even if the screen stayed on all night (checked every 250 ms): that wake is silent (`wake(true)`: no sound, no speech, and the music stays off until the next real tap or key, `musicHold`), and so is a wake from a `storage` or visibility change; a tap on a place wakes everyone with "Good morning!".
- **Timing and cost:** animation time (`time`) uses `dt` capped at 0.1 s; transitions and other waits use real time (capped at 0.25 s per frame), and the pill's pause and the watchdogs use `performance.now()`. The no-hello watchdog is paused while the page is hidden. Glowing windows (the town, the bus, the train) are painted once with their glow into cached sprites (`glowSprite()`) and drawn with `globalAlpha`; they and the painted layers are built after a layout and behind the closed iris (`warmLayers()`), never mid-frame; the evening and night multiply tints are folded into a single fill.
- **Grown-ups:** the gear (top left, launcher and sleep scene only) → a 6–9 × 6–9 times-table check on a keypad (a wrong answer shakes and gives a new sum with a different answer) → limit, today's use, "+5 min today", "Start today again", Done.
- **Sound setting:** `hub-mute` / `hub-music` are the one shared setting for the hub and all games. Every change (the hub's capsule, the M key, a game's `{hub:'sound'}`, a `storage` event) goes through `setSound()`, which saves it and sends a time message at once.
- **Volumes (hub and games):** peak gain per note: music lead about 0.045, music bass about 0.06 (the hub: song `vol` × the music bus's 0.5), effects at most 0.14, nothing above 0.2. Bass notes below about 130 Hz are lifted an octave, since phone speakers don't play them. The hub says "Turn me sideways!" about 350 ms after it sends `hold`, because the game hushes speech on hold and iOS may share one speech queue.
- **Versions:** `APP_VERSION` and `CHANGELOG` near the top of `index.html` (the same number as `APP_VERSION` in `sw.js`). The grown-up settings show a "Version N | What's new" chip that opens `#news`, a scrolling list of every version's changes (DOM cards `.vcard`, so the list can scroll; Esc/Enter close them). Over the launcher or sleep scene only (never over a game, the settings or the sideways card), `verTick()` (every 250 ms) shows: a small "Updating…" note bottom-left while a new service worker installs (only when one already controlled the page, so not on the first install; then "Updated!" for 2.5 s); the "Updated to version N!" card with the first three items, once, when `hub-version` (storage) is older than `APP_VERSION` (a player who never had `hub-version` but has `hub-play` or a service worker counts as updated; a brand-new player is stored silently), and only after the install finished; and "Version N is ready!" (Later / Update now = reload) when the service worker that just activated answers `{type:'version'}` with a newer number than this page (a page served from the cache before the update). The hub calls `reg.update()` at every launch and when it comes back after 30 min hidden. To test the service-worker parts, serve a scratch copy on `localhost` with the https check relaxed, change `APP_VERSION` in the served `sw.js`, and reload.
- **Other storage:** `hub-stars`, `hub-music`, `hub-mute`, `hub-version`. Every access in try/catch; works without storage.
- **iOS audio:** unlocks on pointerup/touchend/click/keydown and sets `navigator.audioSession.type = 'playback'`; buttons fire on pointerup. Hub music stops while a game is open; on leaving a game the hub posts `pause`, cancels speech and removes the frame. `say()` and becoming visible call `speechSynthesis.resume()` (iOS can leave speech paused), and music is only ducked for up to 15 s after the hub last spoke, in case `speaking` sticks.
- **Test hook** `window.__hub`: `open(key, {anyway})` (returns `'rotate'` when the sideways card shows), `exit()`, `state()`, `playTime` (`left()`, `used()`, `share()`, `limit`), `modal` (with `answer`), `layout()`, `buttons()`, `setUrl(key, url)` (point a place at a fake game), `closeRotate()`, `sky(phase)`.

## Design constraints

Gentle for young kids: no game over, no timers except the grown-up's daily limit, which never cuts a child off mid-turn. Pre-readers: big targets, minimal text, spoken names. Touch first. Original characters, tunes and sounds; no copied TV-cartoon looks, real MRT/bus chimes or operator branding. Paper-cut storybook look: flat shapes, a darker crescent on the lower right, rims in a deeper tone, no black outlines.
