# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Let's Play!": an all-in-one app for a ~6–7-year-old that combines three of the owner's games behind one launcher (the "hub") with ONE shared daily play-time limit set by a grown-up. Tablet first, also iPhone.

```
index.html               the hub: storybook launcher, shared play time, grown-up settings, shared sleep scene
games/bus3d/             Little Bus Captain (the 3D bus game the hub opens; first called Bendy Bus 3D): index.html, vendor/three.min.js (three r149, MIT), js/*.js; landscape
games/bus/               the old 2D Bendy Bus, no longer opened by the hub or cached (kept for reference)
games/grizzly/index.html Grizzly and the Lemmings (20 mini games), canvas 960x540, landscape
games/mrt/index.html     MRT Math Express, DOM, portrait-phone first
icons/, manifest.webmanifest, .nojekyll   hosting (icons drawn with the hub's art: node icons/make-icons.js)
sw.js                    the service worker that makes the Home Screen app work offline
```

No build step, no dependencies; everything is drawn and synthesised in code and works offline from `file://` (Little Bus Captain needs WebGL).

The owner reviews as a player, from screenshots and a link, not from code. Report in plain language and send screenshots of visible changes.

## Commands

There is no build step, linter or test suite. The everyday commands:

- **Syntax check** (the only "lint"; a syntax error blanks the whole game): `for f in games/bus3d/js/*.js; do node -e "new Function(require('fs').readFileSync('$f','utf8'))" || echo BAD $f; done`
- **Try it:** open `index.html` (the hub) or `games/bus3d/index.html` from `file://`, or serve the folder with `python3 -m http.server`.
- **Test a change:** copy `games/bus3d` (or the whole app, for hub tests) to a scratch folder and test the copy, never `/home/user`. Headless Playwright needs `chromium.launch({ args: ['--use-gl=swiftshader', '--enable-unsafe-swiftshader'] })` to draw the 3D game at all (a few fps). The usual flow: seed `localStorage['bus3d.save']` (e.g. `{jobsDone: 6, questions: 14, seen: {add: true, sub: true}, vehiclesOwned: [...]}`), stub `speechSynthesis.speak` to log the lines, then click "Play" and "Drive!" with `{ force: true }` (the buttons bob, so normal clicks time out). Jump to the current stop: `const j = BB.jobs.current, s = j.stops[j.index], bay = BB.world.bayOf(s); BB.bus.setPose(bay.nose.x - bay.fwd.x * 3, bay.nose.z - bay.fwd.z * 3, bay.heading); for (let i = 0; i < 60 && !BB.bus.atStop; i++) BB.update(0.05);` and answer by tapping the `.bbq` button whose text is `BB.jobs.question.answer` (pointerdown, pointerup, click). Hub tests: open the hub's `index.html` and call `__hub.open('bus')`, then reach the game with `page.frames()`.
- **Preview build:** the preview Artifact is a scratch copy of the app with the hub stripped by the `sed` line below and `<title>` "Let's Play! Preview". At the owner's request everything is unlocked in it: in the copy's `depot.js`, `ownsVeh`, `partOwned`, the paint and sticker `own` checks return true, both Extras are set (`S.upgrades.horn`, `S.upgrades.sticker3`) and the starting cash is at least 500; after copying in a changed `depot.js`, re-apply all of them and check the shop shows no price chips (the other helpers' edits can move the lines). Those edits live only in the scratch copy; never commit them, and check `grep -c "PREVIEW BUILD" games/bus3d/js/depot.js` is 0 before a release.
- **Release (after the owner says "go"):** bump `VERSION` in `sw.js`, push the branch, fast-forward `main` to it (`git push origin HEAD:main`), confirm the "pages build and deployment" run for that commit succeeded, then rebuild and republish the main Artifact (if this session didn't publish its files, read them with the Artifact tool first, or the publish is refused).

## Published copy

`main` is served by GitHub Pages from the repo root at https://hermannwwr-cmyk.github.io/letsplay/. Every push to `main` redeploys it within a minute or two. Cloud containers usually can't reach github.io (the proxy refuses it), so confirm a deploy with the "pages build and deployment" workflow run for that commit (GitHub MCP `actions_list`). `.nojekyll` turns off Jekyll.

The owner also has a private claude.ai Artifact copy titled "Let's Play!" (https://claude.ai/artifact/3HjW7hseEgPHX7MHT1sJvp). After a change, rebuild it in a scratch folder and republish it to that URL, with the hub as the page and the game files (`games/bus3d/index.html`, `vendor/three.min.js`, `js/*.js`, `games/grizzly/index.html`, `games/mrt/index.html`) as supporting files at the same paths (the games' icons and manifests aren't needed). The host supplies the document skeleton, so strip it and the head tags from the hub:
```
sed -e '/^<!DOCTYPE html>/d' -e '/^<\/\?html/d' -e '/^<\/\?head>$/d' -e '/^<\/\?body>$/d' -e '/^<meta /d' -e '/^<link rel=/d' index.html > lets-play.html
```
Keep `<title>` and `<style>` near the top of `index.html` and each head tag on its own line, so this stays a line deletion. `sw.js` isn't needed in the Artifact (the hub only registers it on https in a top-level page, and a failed registration is ignored).

**Offline Home Screen app (`sw.js`):** a small versioned service worker, registered from `index.html` only when `location.protocol === 'https:'` and the hub is the top window (never from `file://`). On install it precaches the hub, the game files and the icons/manifest (`CORE`; the games' own icons and manifests are `EXTRA`, skipped if missing), then `skipWaiting()`; on activate it deletes every other cache and `clients.claim()`s. Pages and code (`.html`, `.js`, `.css`, `.webmanifest`, navigations) are network-first with a cache fallback, fetched with `cache: 'no-cache'` so GitHub's `max-age=600` doesn't delay a push (a cheap 304 when unchanged). An error answer (404, 503) or a network slower than 4 s falls back to the cached copy (the fresh copy still lands in the cache), so a push shows up on the next launch with a connection. Redirected responses, or ones whose URL isn't the requested file (a Wi-Fi login page), are never cached. A redirect or a different page while online is treated like an error answer (the cached copy is used). A failed install removes the empty new cache; icons and images are cache-first; the bus game's Google Font is cached at runtime in `lets-play-fonts`. Lookups ignore the query string (games load as `index.html?hub=1`). **Bump `VERSION` in `sw.js` on every release** (any change to `index.html`, `games/` or `icons/`), and add new files to `CORE`: a missing `CORE` file makes the install fail and the old copy stays. To test it locally, serve a scratch copy and relax the https check to allow `localhost` (a secure context); Playwright's `context.setOffline(true)` after a first load simulates the offline relaunch.

**Previewing before going live:** a push to `main` goes public at once, so visible changes are shown to the owner first and pushed to `main` only after they say go. Show options as screenshots (before/after sheets at phone and iPad sizes), then build the chosen one into the preview Artifact "Let's Play! Preview" (https://claude.ai/artifact/TsjDv2hfXpHCB2ba5Lv4v5; same build, with `<title>` changed to match). Meanwhile commit the work to the `claude/dazzling-albattani-67ajm8` branch (Pages doesn't serve it), then fast-forward `main` to it on approval and republish the main Artifact.

## Where the games come from

The games are copies of the owner's standalone games, plus a small "hub mode" patch in each:
- Bus: Little Bus Captain (first called Bendy Bus 3D) was built here (`games/bus3d/`, brief in `games/bus3d/SPEC.md`, partly outdated (where it and this file disagree, this file wins): the owner later chose free driving with a steering wheel and Go/Back pedals (the only control; the joystick was removed) plus an optional lane helper, left-hand traffic, two lanes each way, side-view stops with a dollhouse cut-away, three generic Singapore bus types plus five drivable vehicles (taxi, fire engine, ambulance, ice cream van, tow truck), real parts in the garage, no faces on vehicles, a written sum with pictures, a 6-minute day cycle with ~30 s of night, weather). It has no standalone repo; the old 2D bus came from the `Bendy-Bus-Game` repo's `gh-pages` branch.
- Grizzly: the `Grizzly-and-the-lemmings-game` repo's `index.html` (its CLAUDE.md documents the game in depth).
- MRT: the `MRT-GAME` repo's `index.html` (its CLAUDE.md and `tests/play.js` document and test it).

Hub mode only switches on with `?hub=1` inside an iframe (`const HUB = /[?&]hub=1\b/.test(location.search) && window.parent !== window`). Without it each copy behaves exactly like the original. To bring in a newer version of a game, re-apply that game's hub-mode code (everything guarded by `HUB`, plus the hub-only CSS) to the new file. The hub-mode code exists only here, not in the original repos. This repo starts from a single import commit, so diff `games/<game>` against the original game's file to see exactly what hub mode adds (the step-by-step history is on the `claude/dazzling-albattani-67ajm8` branch of `Bendy-Bus-Game`, where the app was first built; that branch is no longer updated).

## Hub ↔ game protocol (postMessage, always to `'*'`)

In `file://` the frames have opaque origins, so never touch `parent.document` and don't rely on storage shared between hub and game. Ignore messages that aren't objects with a `hub` string; games also check `e.source === window.parent`, and the hub checks that messages come from the current frame.

| from → to | message | when |
|---|---|---|
| game → hub | `{hub:'hello', game}` | script start; the hub closes a frame that hasn't said hello within ~6 s |
| game → hub | `{hub:'exit'}` | child taps the "all games" button |
| game → hub | `{hub:'sleep'}` | the game's own gentle bedtime ending has finished; the hub treats it as the end of the day |
| game → hub | `{hub:'stars', count}` | optional, for the stars shown on the launcher |
| game → hub | `{hub:'sound', mute, music}` | the child tapped the game's own 🔊 or 🎵: the full new shared setting (both booleans). The game applies it at once; the hub saves it (`hub-mute`, `hub-music`), updates its own icons and sends a time message straight back with it |
| hub → game | `{hub:'time', limit, left, used, share, mute, music}` | about every second, on hello, and at once whenever the sound setting changes; `left` is null and `share` 0 when the limit is off. `mute: true` = all sound off (music, effects, voice); `music: false` = music off only |
| hub → game | `{hub:'hold', on}` | `on:true` when the "turn me sideways" card covers a running game, `on:false` when it goes. The game freezes (no updates, timers or speech, sound suspended) and then carries on exactly where it was. Bus re-says the line that was cut off, or the question on screen. MRT is never covered and ignores it. |
| hub → game | `{hub:'pause'}` | right before the frame is removed |

In hub mode every game: doesn't count time or touch its own play-time storage; doesn't read or write its own saved sound/music switches (it starts with sound and music on until the first time message, which comes on hello, and its buttons always show the hub's values; its 🔊 means all sound off); hides its own grown-up gear/gate/settings; shows the shared **all-games button** top-left on its start screen (a 64px cream paper circle, at least 56 CSS px on phones, fill `#fff6e0`, rim `#d9b57f`, with a 2×2 grid of rounded cards `#f26b5b` `#f5b83d` / `#5cb85c` `#4fa3e0`, bobbing gently); shows the shared clock chip look (cream pill, drawn clock, m:ss, orange with a moon in the last minute); runs its own gentle bedtime ending and then posts `sleep` once; never starts a new round once time is up; and fills the screen around its canvas with a cheap continuation of its own scene (Grizzly, Bus; no per-frame pixel reads, no CSS blur, dimmed and tinted with the picture). All three send `hello` at the end of their setup.

- **Grizzly:** the menu gear spot becomes the all-games button (grown by `hubExitR()` on small screens, with the "N min" chip moved along). Round games check `lastTurn()` before starting a new round: once `timeUp()`, the next finished turn gets a sleepy "Goodnight!" card and line, then `sleep` (Grizzly's own sleep scene and speech never show in hub mode). Continuous action games (Leap, Rafts, Bounce, Boop, Catch, Stack) freeze their difficulty and tips once time is up and say goodnight at a calm moment about `CONT_GRACE` (35 s) after zero, never mid-jump; `BEDTIME_GRACE` (150 s) is the last safety net. The backdrop (`hubBackdrop()`/`paintHubBackdrop()`) is a half-resolution canvas repainted at most twice a second: canopy or sky on top, meadow below, and on phones a vertical gradient of the scene's layers (`hubSideStops()`). The main loop's update/render is wrapped in try/catch so one error can't freeze the game.
- **MRT:** `#homeClock` becomes the all-games button (inline SVG), and the all-games button also shows on the end screens. In hub mode `<html>` gets a `hub` class for layout tweaks that fit the hub's inset iPhone frame (about 390×763). Its "2 more stops" flow starts at 60 s left (at once if a ride starts with 60 s or less), so its bedtime ride usually ends before zero; the train always says goodnight (also when time runs out on the start screen or a normal end screen, after "Hooray!"), and `sleep` is posted ~7 s into the sleepy end screen. Direction signs on the start picker and at interchanges take two taps: the first lights the sign and speaks where it goes, the second takes it. On sideways screens the game screen splits into station (left, sized by `fitScene()`) and question (right) with no scrolling.
- **Bus (Little Bus Captain, `games/bus3d/`):** three.js scene, classic scripts sharing `window.BB` (core, fleet, world, bus, jobs, depot, ui, main). Opens on its own home screen (title, the child's bus, one big Play button to the garage, a friends count); the garage has the ride (bus types and the other vehicles), colour, number, parts shop, settings and free fuel. Hub mode: clock chip, last-minute warning between stops (never during a question; `BB.jobs.busy()`), the sky eases to night in the last minute, goodnight after the stop in progress (passengers walk off, lights off, "Goodnight, bus!") then `sleep` once; never starts a new job after time is up. `{hub:'stars'}` = jobs done. Hold and a hidden page freeze the loop and `BB.later` timers; use `BB.later`/`BB.cancelLater`/`BB.wait` for new timers. The all-games button (with a "Home" tag) is on the game's home screen only; the driving HUD's and garage's Home tiles go back to that home screen.

## Little Bus Captain (`games/bus3d/`)

About 17,000 lines of classic `<script>`s (not ES modules, which fail from `file://`) sharing one global `window.BB`, loaded in this order by `index.html`: `vendor/three.min.js` (global `THREE`), `core.js`, `landmarks.js`, `fleet.js`, `world.js`, `bus.js`, `jobs.js`, `depot.js`, `ui.js`, `net.js`, `events.js`, `main.js`. Each file adds its own CSS through `BB.css`. Modules talk through an event bus (`BB.on(name, fn)` / `BB.emit(name, data)`); grep `BB.emit('` for the full list.

### Modules

- **core.js:** the event bus, `BB.store` (localStorage keys `bus3d.*`, try/catch) and `BB.save` (one object saved as `bus3d.save`: paint, parts/partsOwned, stickers, upgrades, fuel, jobsDone, questions, `skill`, `wish`, `seen`, busType, routeNo, assist, leftHand, control; `DEFAULT_SAVE` plus checks on load), `BB.mk` (merges flat-shaded vertex-coloured parts into one mesh), `BB.pic` (flat canvas icons), sound effects and the looping tune, `BB.say`/`BB.heard` (a warm storyteller voice when the device has one: `KID_VOICES`, e.g. Samantha/Karen/Moira on Apple devices, Google UK English Female on Android; rate 0.88, pitch 1.1), hold-aware timers `BB.later`/`BB.cancelLater`/`BB.wait`, `BB.setHeld()`, and hub mode (`BB.HUB`, `BB.hub`, the protocol).
- **fleet.js:** `BB.fleet.build(type, paint, opts)` for the three bus types (`bendy`, `double`, `single`; generic, no branding): carriages, hitch, axles/wheelbase, door proxies, `seatsLocal` (10 seats, ten-frame order; row 2 raised and offset half a seat so both rows read from the side), `kerbWallParts` (faded at stops for the dollhouse view), `roofParts`, part mounts, wipers, `routeSign.setNumber()`. Paint uses a shader patch (paint-flagged vertices take `material.color`); doors and wipers move in the vertex shader. `preview()` makes the garage tiles.
- **world.js (`BB.world`):** the town on a road graph (`nodes`, `edges` with `points`, two lanes each way, left-hand traffic; `C.block`, `C.roadHalf`, `C.lane` set here), 61 stops with picture signs (11 named, the rest small automatic stops) plus about 67 roadside scene spots for the other vehicles, the depot, landmarks, HDB blocks, decorative cars on an outer ring, `colliders` (`addCircle`/`addBox`/`pushOut`, `blocksSight` for cameras), the day cycle (`setDayTime`, `day`, `night()`; in hub mode the last minute eases to night and stays) and weather (`setWeather`, `isRaining`, rain as one draw call). `prewarm()` compiles the weather shaders at load.
- **bus.js (`BB.bus`):** free driving from `B.input` (`{analog, throttle, steer}` from the joystick or wheel, or the old booleans), trailer physics for the bendy, collision circles that slide along colliders (never stuck: slide, then hop free), the optional lane helper (`B.assist`: follows the ribbon, hands over to parking in the last ~34 m), the guide ribbon, settling into a bay and `bus:arrived` (forgiving: anywhere from 8 before to 12 past the box, either lane on that side, at up to a gentle roll (speed < 7), then a 0.5–1.1 s glide in, so a child never has to reverse), `stopAt(stop|depot|null, cb)`, fuel, the turn-around hop, cameras (`setCamera`: chase, the side-view stop camera chosen once per stop/bus type/screen size: on tablets, where the card is along the bottom, the bus stands just above the card and the people come first, so a long bus's tail may be cut off; depot views), `setType`, `setRouteNumber`, `setPart` (lights, bumpers, wheels, rims), stickers, `makeTowTruck()` (one cached truck), `seatWorld(i)`, `doorWorld()`, `exitDoorWorld()`.
- **jobs.js (`BB.jobs`):** jobs of 2–3 stops, people queueing, boarding by the front door and leaving by the exit door, `makeQuestion` (every number 0–10, adding first, taking away later, no repeats in the last 5, "0 left" at most once in 5 questions), difficulty that follows the child (`save.skill` 0–4.6, its whole part is the level in `LEVELS`: +0.4 for a right answer at the first try, unchanged after one wrong try, −0.6 when Mina had to walk through it; nothing is shown or said about it), shuffled answer choices (tappable as soon as the question starts being asked; a tap on the still-faded buttons during the story makes Mina hop with a soft tick and never cuts the story off), short varied hello and praise lines (never the same twice running), the question card (ten-frame plus the written sum `2 + 1 = ?` with person icons under each number), teaching on the real bus (outline rings and number bubbles over heads, Mina the mynah; 1st miss = count together by tapping, 2nd = Mina stops at "?", 3rd = shows it all; first-time worked examples use other numbers), the tow, coins (1 per stop + 2 per finished job, about 50 a day at 15 minutes: slower on purpose, the owner's choice; never taken away), `busy()` / `jobs:busy`, `allOff()` for the goodnight.
- **depot.js (`BB.depot`):** the garage (reached with Play from the home screen; it has a Home tile), in three big labelled sections: My ride (vehicle picker, colour, number keypad for buses), Shop (Stickers, Lights, Bumpers, Wheels, Extras sub-tabs) and Settings (pedals on the right/left, lane helper, Christmas). Tapping a section or tile moves the camera to the part (`garageWhole`, `garageFront`, `garageWheels`, `garageSide`, `garageSign`, `garageRear` in bus.js). Every tile has a picture and a word, price chips on things not owned, a teal rim and tick on the chosen one; try on with one tap, buy with a second ("Tap again to buy!"), then a show-off close-up; one big labelled "Drive!" button. Fuel is free and filled on every visit (the tank shows only while it fills). Cash is `BB.depot.cash` (`cash:changed`). **The wish** (`BB.depot.wish()`): the ride the child is saving up for, i.e. the locked ride they tapped last in the garage (`save.wish`), or the cheapest one not bought yet; its tile has a little bar that fills with the coins, tapping it says how many more coins it takes, the job-done banner shows its picture, the bar and the coins still missing (spoken: "10 more coins for the ice cream van!", or that there are enough, at most three times), and the coins tile says it too.
- **ui.js / main.js:** the HUD: cream paper tiles, each a picture (most with a word under it) and spoken on tap, all icons drawn in one paper-cut style in `core.js` (`BB.pic`). The owner asked for fewer buttons and more view while driving, so it is kept small: Home and one coins + fuel-dial tile top-left; Next stop in the middle (vehicle jobs show their own picture and word); Garage and Sound top-right; at the bottom only the steering wheel (a quick tap on its red middle honks; three quick honks = the secret turbo) and the Go/Back pedals, plus Turn around or Wash when needed. Music and the lane helper are in the garage's Settings; the sirens switch with the jobs (no Siren tile). The chase camera sits a little lower and looks further ahead (it looks down more under the MRT viaduct). Home goes to the game's home screen (a kept job resumes after Play and Drive), after a spoken "Go home?" Yes/No card while a job, stop or garage trip is on; only the all-games button on the home screen posts `{hub:'exit'}`. Fredoka is embedded in `index.html` (no web font). Also boot order, renderer (pixel ratio ≤ 2), resize, the main loop (`update`/`render` each in try/catch; paused when hidden or held), and the hub-mode flow (welcome, bedtime goodnight).
- **net.js (multiplayer, automatic):** whenever online every device joins public world rooms on the owner's Cloudflare relay by itself (`RELAY = 'wss://bus-captain-rooms.hermannwwr.workers.dev'`, rooms `lbc-world-1…200`, max 10 each; a full room → the next; alone in a higher room → regather to lower ones); no codes, no chat or names; incoming state is validated/clamped; in world mode each device keeps its own sky. A private 'family' mode still exists in net.js (`setMode`), but the garage no longer exposes it and saved family mode is forced back to world on start. Friends show as a count on the home screen and chips while driving. Relay code in `relay/` (`worker.js`: Worker + one Durable Object per room; `/health`, `/check` (tests the Durable Object: "rooms ok"); `wrangler.toml` with the migration and `ALLOWED_ORIGINS`). The Worker is deployed by Cloudflare Workers Builds from `relay/` on `main` (deploy command `npx wrangler deploy`) — a change in `relay/` on main redeploys it; don't bind ROOMS to another Worker's namespace. Test locally with `npx wrangler dev` and `?relay=ws://127.0.0.1:8787`. The claude.ai Artifact sandbox and this container's proxy block the relay; real tests happen on the owner's devices.
- **landmarks.js (`BB.landmarks`):** an art kit of generic Singapore-inspired models (no names, logos or exact replicas): observation wheel, super-trees, skyline towers, airport terminal, control tower, planes, runway, Chinatown row, beach park, elevated-road kit, depot pieces (parked buses, fuel island, bus wash, gatehouse, boom gate, big workshop) and Christmas decorations; each returns a Group with `userData` footprint/colliders; `batch()` merges many into one draw call; `update(dt)` animates and lights them at night.
- **events.js (`BB.events`):** busy-town events staged 25–40 m ahead on the bus's route and only announced once visible: fire truck, ambulance (make way → coin), police and runaway trolley/balloon, breakdown and tow, ice cream truck (2-coin treat), milk van, rubbish truck, otters crossing, parade, fireworks and a landing plane (camera look-up via `BB.bus.lookAt`), rainbow puddles. One at a time, never near a stop or during a question, no repeat within 8 minutes, hold-aware. `BB.events.trigger(name)` is a debug hook. First sightings emit `spot` and fill `BB.save.spotted` for the spotter book (Book tile on the home screen and garage: "Things I spotted" and "My passenger friends").

### Gameplay

- **Vehicles:** fleet.js also builds 'taxi', 'fire', 'ambulance' (heart emblem, never a red cross), 'icecream', 'tow' (`BB.fleet.KIND`, siren, ladder/hatch/boom/hook); unlocked with coins in the garage's "My ride", in any order (`VEH_PRICE`: taxi 40, ice cream 60, tow 80, ambulance 100, fire engine 120; `vehiclesOwned`, per-vehicle paint); each has its own job in jobs.js (picture questions + 3D scene props: bags, firefighters in one well-spaced line/smoky windows, teddies, ice creams, yard cars). They never use bus stops: their own stops are `W.sceneSpots` (plus `W.places` when near), and the target shows that ride's marker from far off (`placeMarker`: a round sign on a pole with the taxi / heart / ice cream picture, a smoke column for the fire, the broken-down car and a warning triangle for the tow). Every counted thing has the same colour on the card and in 3D (seated passengers take the boarding person's colours via `BB.bus.setSeatLook`; `bagColor(i)` for bags and suitcases).
- **Beginners:** the lane helper is on by default (the owner's choice); it is off only when a grown-up turned it off in Settings (`save.assistChosen`). When the child is no nearer the target by road for ~15 s, a spoken hint (hold the green pedal / tap turn around / follow the yellow arrows; at most every 40 s, `updateLost` in jobs.js).
- **Driving extras:** 61 stops ~70 road units apart (most are small automatic stops, `st.minor`), jobs pick the next stop 40–80 units on (~8 s); town top speed ~10.8 for buses; a secret turbo (honk 3× quickly → `BB.bus.boost()`, 20 s cooldown, refused near the bay with a fizz); cabin lights at night (`setCabinLight`); `B.holdArrival(s)` lets events delay parking.
- **Special jobs and friends (jobs.js):** after 3 jobs, sometimes a school run (morning), airport rush (sometimes counting suitcases), party bus, or a rainy-day bonus stop; recurring passenger friends (`BB.jobs.FRIENDS`, `friend:met`, `BB.save.friendsMet`). The first 3 jobs pick nearby stops.
- **Bus wash:** dirt builds while driving (`BB.save.dirt`, cosmetic); a Wash tile leads to the wash bay; a 3-coin pay card; `BB.bus.wash()` runs the show; coins are refunded on load if a paid wash didn't finish (`washPaid`).
- **Christmas mode:** `BB.xmas` (Settings: Auto 1 Dec–6 Jan / On / Off), public-domain carols in our own arrangement, decorations, star sparkles (no snow), festive lines.

### Town and looks

- **The map (world.js):** the town loop plus an outer road, an expressway (north), the airport (east), city towers, old town, the waterfront (wheel, gardens) and a beach; 61 stops (11 named); an open-air depot (yard bays, parked buses, fuel island, drive-through wash, workshop, gates) — after Drive the bus starts parked in the yard's middle parking area between the parked buses (the owner's choice: bays 1, 3 and 5 of the 7, `PARK_START`, kept empty, nose to the south aisle; ~18–23 s to the first stop), taking the first one with no friend's bus in it (multiplayer, `BB.net.busSpots()`); then the spare start bays (`W.startSlots()`: the yard's way out by the gate (`W.yardStart`), the inner lane beside it, both lanes each way on the road between the two gates; `BB.bus.startBay()`), and drives out (`inDepotYard`, `bus:leftDepot`); the Garage tile and low fuel don't make the child drive back: `J.goDepot` fades straight into the garage (the job waits and resumes after Drive); far areas are culled. `setXmas(on)` adds decorations. `stopDistance`, `stopsByDistance`; `C.fuelPerUnit` = 1/6500.
- **Scenery extras (world.js):** two layers of far paper hills are drawn inside the sky shader (`hill1`/`hill2`, tinted with the sky, sinking into the mist in rain; no mesh); a ring of low cloud banks sits just above them (the driving camera looks down, so these are the clouds it sees); `buildMeadow()` scatters paler grass scraps, flower clumps and low bushes along the roads with its own random numbers (`drnd`, so the town's layout never shifts), no colliders, bushes 11+ from the road edge (clear of the kerb-side scenes), in one `meadow` mesh of about 4,000 triangles; the sea has pale wave streaks and `seaGlints` (twinkles in a vertex shader, one draw call near the waterfront, off at night). At night the vehicle's headlights are two soft beams from its lamps plus a warm oval pool on the road ahead (`lightCones`/`lightPool` on the model's `lightsFront` mount, bus.js). Vehicle shadows use one soft rounded-rectangle texture (`BB.mk.blobTex`). The home screen has the garage's striped awning along the top.

### Performance and testing

- **Performance budget (older iPads):** about 25–50 draw calls and ≤ ~100k triangles; merged or instanced meshes, blob shadows, no shadow maps, fog. Measured with the chase camera 30 units before each of the 60 stops (iPad size): about 58k triangles in the middle case and 87k in the busiest views (the old town and the town centre), 39–52 draw calls. The static town meshes are built "lean" (`lean(builder)` in world.js sets `trim` and `pack`, read by `Builder.geometry()` in core.js): `trim` leaves out triangles no camera can see (undersides of things standing on the ground or pavement, i.e. down-facing below 0.36, since the lowest camera is the garage's wheel view at 0.75; anything under the ground; the hair-thin sides of painted road markings), about a fifth of the town; `pack` stores normals and colours as bytes (town geometry about 10 MB instead of 20). After `geometry()`, `builder.counts` holds the vertices each part kept: per-vertex extras (`aCenter` for fading props, `aGlow` for landmark lights) must be sized from it, after the mesh is made. `geometry()` never changes a part's shape, so unit shapes are shared (`box`, `cyl`, `ball` reuse one shape each and scale it in the part's transform). Vehicles, people and anything whose arrays are copied elsewhere (net.js) are not lean. Colliders are stored by `addCol` with the same fields in the same order, and `W.pushOut` (about 25 calls a frame) uses plain loops and plain-number bounds: keep it that way, it is the hottest function while driving. Automatic quality in main.js (`adaptQuality`): when frames stay slow (smoothed frame time over 25 ms for ~3 s) the pixel ratio steps 2 → 1.6 → 1.3 → 1, and back up after a long smooth spell (at most twice). Keep per-frame code free of garbage: no new objects/arrays in update paths (reuse scratch objects, index loops in hot code, `hypot2()` instead of `Math.hypot`); the stop camera is planned once per stop and frame set.
- **Testing:** drive by script through `BB.bus.input`/`BB.bus.setPose`, `BB.bus.setType`, `BB.jobs`, `BB.depot.open()`, `BB.world.setDayTime/setWeather`; stub `speechSynthesis.speak` to log speech. Test a scratch copy (never serve `/home/user`), one browser at a time.

## The hub (`index.html`)

One canvas, in the Grizzly paper-cut art style (its art kit, palette and the embedded Fredoka font were copied in).
- **Finding your way** (one IIFE, about 3,000 lines): `GAMES` (url, name, spoken name, colour per key) and `ORDER` near the top, then `playTime` with `DEFAULT_LIMIT`, `LIMIT_CHOICES` and `FORCE_SLEEP_AFTER`; the art kit and the heroes (`drawBear`, `drawLemmingAt`, `drawBusHero`, `drawTrainHero`); `layout()` (landscape and portrait placement of the places, path and props); `SKY` and the tints; one `draw<Game>Place()` per place; then the frame lifecycle (`openGame`, `sendTime`, `closeGame`, `updateTransition`, `goSleep`, `LANDSCAPE_ONLY`, `showRotate`/`showOver`/`checkRotate`, `reloadPlayTime`). A fourth game would need a `GAMES`/`ORDER` entry, a place in `layout()`, a `draw…Place()`, a loading scene, and hub mode in the game itself.
- **Launcher:** a panoramic storybook world with three places on paper islands joined by a path: the bendy bus at its stop (Little Bus Captain; long names get smaller letters via `nameFit()`), Grizzly and the lemmings, the MRT train on a viaduct. Places idle-animate and take turns doing a "look at me" act. A tap pops (pointerdown), then on pointerup squashes, plays a sound, speaks the name, throws confetti, zooms in and closes an iris in that game's colour with its hero bouncing while the frame loads. Landscape: places side by side; portrait: zig-zag down the hills. Arrow keys / Enter / 1–3 / M work too.
- **Turn sideways:** Grizzly and Bus are landscape games. On a portrait screen the hub shows a "Turn me sideways!" card instead, opens the game when the device turns, and covers a running game (not counting time) if it's turned back upright, also while the game is still loading or being revealed (the hold is sent again when the game says hello). MRT opens in any orientation. On a tablet-sized screen (`min(screen.width, screen.height) >= 700`) whose window clearly doesn't fill the screen either way round (`narrowTabletWindow()`: iPad Split View, Slide Over, Stage Manager) the card also offers a small "Play anyway" button (`playAnyway()`, sets `state.anyway` so that game isn't covered again until it closes); a full-screen iPad held upright and phones never show it.
- **Game frame:** Bus and Grizzly get the whole screen (they letterbox their own canvas, with buttons clear of the notch). MRT, edge-to-edge DOM, gets an inset frame (`iframe.game.inset`, inset by the hub's safe areas `--sat` etc., since WebKit doesn't pass them into frames), so it isn't under the notch or home indicator; `paintFrameBg()` paints the strips in MRT's own page colours (start-screen sky gradient with the viaduct deck under it, its night sky on the sleepy end screen, `--bg` otherwise), reading MRT's `body[data-screen]` / `.night` in a try/catch when the frame is same-origin and using the start-screen colours from `file://`. On the start screen the sky is laid over the frame's area so it carries on into the side strips, the top strip is MRT's exact top colour and its sun glow continues across the seam, and `#frameDock` / `#frameDeck` copy MRT's `.start-dock` background (flats, trees, viaduct) into the strip on the dock's side and its deck colour under it (read every 400 ms). While a game fills the screen (`gameShown()`), the hub's draw loop and music scheduling stop and its canvas and painted layers are freed (`sleepLoop()`); `wakeLoop()` restores them (closing, the sideways card), lays out again if the window changed meanwhile, and the painted layers are rebuilt behind the closed iris (`warmLayers()`). `resize()` does nothing when the size, DPR and safe areas haven't changed; clouds, birds and fireflies keep their own random numbers so a resize re-places rather than reshuffles them.
- **Play time:** storage `hub-limit` (minutes, default 15; Off/10/15/20/30) and `hub-play` = `{day:'Y-M-D' (no zero padding), used: seconds, extra: minutes}`. Counts whole seconds only while a game frame is showing (after hello, no transition, no modal, no sideways card, page visible), and never past the allowance. Re-reads on `storage` events and when the page becomes visible. The top bar is small paper pieces: a borderless cog (grown-ups) top-left, a cream time pill beside it (a sun in a ring that empties and turns into a moon; orange in the last minute; tapping it speaks the minutes left, at most every 3 s of real time, and never opens settings). Minutes left are shown and spoken the same way everywhere (`fmtLeft`): whole minutes rounded up, and "under 1 min" in the last minute (pill, speech and settings), and one music|sound capsule hanging on short strings top-right (no strings below 420 px height). Positions come from `barGeom()`, clouds fade out behind the bar (`cloudClear()`), and the portrait title sits below the bar; the sky follows `share()` from dawn to night, with warm window and lamp light drawn after the night tint.
- **Bedtime:** at zero the game finishes the turn and posts `sleep` (fallback: force-sleep 3 minutes past zero). A `sleep` that arrives while the frame is already closing because the child chose to leave is ignored (the closing still goes to bed if the time is up). The shared sleep scene shows everyone asleep with a lullaby (drawn at about 30 fps; on upright screens the "Time to sleep!" card moves up and shrinks to stay above the sleeping train's station); places can't be opened; it survives reloads. Adding time in the settings wakes everyone. A new day also ends the sleep scene, even if the screen stayed on all night (checked every 250 ms): that wake is silent (`wake(true)`: no sound, no speech, and the music stays off until the next real tap or key, `musicHold`), and so is a wake from a `storage` or visibility change; a tap on a place wakes everyone with "Good morning!".
- **Timing and cost:** animation time (`time`) uses `dt` capped at 0.1 s; transitions and other waits use real time (capped at 0.25 s per frame), and the pill's pause and the watchdogs use `performance.now()`. The no-hello watchdog is paused while the page is hidden. Glowing windows (the town, the bus, the train) are painted once with their glow into cached sprites (`glowSprite()`) and drawn with `globalAlpha`; they and the painted layers are built after a layout and behind the closed iris (`warmLayers()`), never mid-frame; the evening and night multiply tints are folded into a single fill.
- **Grown-ups:** the gear (top left, launcher and sleep scene only) → a 6–9 × 6–9 times-table check on a keypad (a wrong answer shakes and gives a new sum with a different answer) → limit, today's use, "+5 min today", "Start today again", Done.
- **Sound setting:** `hub-mute` / `hub-music` are the one shared setting for the hub and all games. Every change (the hub's capsule, the M key, a game's `{hub:'sound'}`, a `storage` event) goes through `setSound()`, which saves it and sends a time message at once.
- **Volumes (hub and games):** peak gain per note: music lead about 0.045, music bass about 0.06 (the hub: song `vol` × the music bus's 0.5), effects at most 0.14, nothing above 0.2. Bass notes below about 130 Hz are lifted an octave, since phone speakers don't play them. The hub says "Turn me sideways!" about 350 ms after it sends `hold`, because the game hushes speech on hold and iOS may share one speech queue.
- **Other storage:** `hub-stars`, `hub-music`, `hub-mute`. Every access in try/catch; works without storage.
- **iOS audio:** unlocks on pointerup/touchend/click/keydown and sets `navigator.audioSession.type = 'playback'`; buttons fire on pointerup. Hub music stops while a game is open; on leaving a game the hub posts `pause`, cancels speech and removes the frame. `say()` and becoming visible call `speechSynthesis.resume()` (iOS can leave speech paused), and music is only ducked for up to 15 s after the hub last spoke, in case `speaking` sticks.
- **Test hook** `window.__hub`: `open(key, {anyway})` (returns `'rotate'` when the sideways card shows), `exit()`, `state()`, `playTime` (`left()`, `used()`, `share()`, `limit`), `modal` (with `answer`), `layout()`, `buttons()`, `setUrl(key, url)` (point a place at a fake game), `closeRotate()`, `sky(phase)`.

## Design constraints

Gentle for young kids: no game over, no timers except the grown-up's daily limit, which never cuts a child off mid-turn. Pre-readers: big targets, minimal text, spoken names. Touch first. Original characters, tunes and sounds; no copied TV-cartoon looks, real MRT/bus chimes or operator branding. Paper-cut storybook look: flat shapes, a darker crescent on the lower right, rims in a deeper tone, no black outlines.
